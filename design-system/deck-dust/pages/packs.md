# 开包工具 UI 与原系统对应

以下为 2026-10-26 的历史设计与实现记录，当前功能交付状态以 `../../../DEVELOPMENT.md` 和运行源码为准。开发过程截图、预览与对比输出已于 2026-10-27 清理。沿用深木色导航、羊皮纸内容区与铜金控件。

## 用户七处批注与页面职责

| 原系统区域 | 新页面 | 对应行为 |
| --- | --- | --- |
| 开包数据统计表 | 开包总览 | 按扩展包名称与卡包类型分组，保留全部指标 |
| 自动合并的开包历史 | 开包分析 | 以任意传说出货结束一个区间，出货的本次录入计入该区间；后续另起一段 |
| 最近开包历史弹窗 | 开包记录 | 每次录入分别保留，不受合并区间影响 |
| 卡牌详情记录弹窗 | 开包记录的“最近实包记录” | 逐包五张卡面、时间、系列、品质与日期选择 |
| 监控与录入表单 | 记录页监控区、新增记录弹窗 | 监控状态、待确认、手动录入预览 |
| 扩展包选择与新增 | 共有筛选、扩展包管理 | 允许同名系列对应不同卡包类型，支持新增与编辑 |
| 保底计算 | 共有右栏 | 指定系列与类型后，分别展示适用品质的进度、已开、剩余、规则上限 |

直接打开：`/#pack-records`、`/#pack-analysis`、`/#pack-overview`。不指定扩展包时展示全部明细、全部区间或全部统计，不把不同系列/类型合并成一个区间。

## 数据与计算展示口径

- 普通、稀有、史诗、传说、金白、金蓝、金紫、金橙、异画传说九种品质分别展示。详情保留零数量，历史表显示破折号，筛选合计显示数字。
- 合并区间按“名称＋类型”独立，从早到晚积累。普通、金色、异画传说任一种出现即结束当前段。区间可以追溯原始录入明细，编辑或删除演示明细后重算区间。
- 日期范围筛选区间时，先用完整明细合并，再按区间最后开包时间筛选，避免在日期边界人为截断。
- 开包总览字段：扩展包名称、类型、总累计开包数、总金色传说、总异画传说、总传说、史诗卡概率、传说卡概率、平均每包尘值、平均每传说包数。
- **按用户纠正：史诗卡概率＝（普通史诗＋金色史诗）÷总卡数；传说卡概率＝全部品质传说÷总卡数。总卡数＝包数×5。** 旧后端史诗概率除以包数的错误不照搬。
- 平均每传说包数＝总包数÷传说张数；没有传说显示破折号。
- 尘值暂沿用旧后端的 5/40/20/100/100/400/400/1600/1600 对应估值与整数截断，不代表特殊品质实际可分解；接入真实功能时单独核对。
- 保底预览使用旧项目已配置规则：普通包史诗 10、普通传说 40、金传 361、异画 361；金色包金传/异画 40；异画金色包金传 40、异画 14。不同品质独立倒序累计。没有指定系列时提示选择，不展示跨系列的假进度。此处是旧规则预览，并非对当前游戏规则的核实。

## 界面结构和状态

主区为筛选、四项汇总、完整台账/区间/总览、选中摘要与页脚；右栏为监控和保底。长表使用局部横向滚动，历史表提供左右按钮，系列名与操作固定，合计固定于表格底部。960px 以下辅助栏下移，640px 以下筛选换行、指标两列。导航保留可访问名称。

弹窗包括新增/编辑记录、删除确认、独立记录详情、区间原始明细、扩展包管理、最近实包记录、日志设置。普通包自动补足普通卡；金色包自动补足金白。数量超出每包五张时阻止保存。

最近实包弹窗展示最近十包并允许继续展开；日期无结果有明确空状态和全部日期按钮。卡面是界面示例，没有关联真实日志，不将手动批量录入伪装为逐包卡牌。

## 日志设置

自动获取按钮包含查找中、检测尚未接入、手动回退状态；实际扫描安装目录未实现。目录旁的感叹号提供悬停和键盘聚焦说明，说明从战网定位安装位置、选择 Logs 根目录、不要选择单个 Net.log 或日期子目录。

用户手动填写并保存后，路径及选项保存在当前应用来源的本地存储 `deck-dust-pack-log-settings-v1`；刷新/重新打开设置回显。未保存取消不覆盖原配置，保存失败提供错误提示。该记忆行为已经可用，实际日志读取与启动监控仍未接入。

## 图标与动效

品质宝石和粉尘瓶从 Hearthstone Deck Tracker 的公开游戏素材按原样保存，运行时离线加载。来源和版权说明保留在 `../../../assets/pack-icons/README.md`；金色与异画为文字角标，不伪称独立原生贴图。未继续使用原先的 CSS 宝石占位形状。

按钮按压缩放 0.96 / 150ms；悬停只在支持 hover 的设备显示。行与筛选即时反馈，开关用可逆过渡，弹窗进入 220ms、关闭图标/Escape 退出 150ms。全局减少动态效果规则优先，禁用位移和缩放；功能状态仍以文字、色彩和选中态显示。

## 后续批注调整：表格、日期和卡牌预览

- 详情数量区排为两行四列：第一行普通/稀有/史诗/传说，第二行金白/金蓝/金紫/金橙；异画传说单独位于右侧跨两行。
- 历史表统一暖纸色、细分隔线和中性色数字，品质用图标区分，选中态改为浅金标记。固定列与数据行使用一致底色，滚动时表头不被固定单元格遮挡。
- 总览十个数据列表头均可排序，第一次点击该列为降序，再次为升序；有方向箭头与 aria-sort，支持 Enter/Space。缺失的平均每传说包数显示破折号并始终排在最后。
- 日期控件只提供有卡牌明细的实包日期，其他日期禁用且置灰；允许跳转有记录月份。Esc 优先关闭日历，不关闭实包弹窗。实包弹窗的标题与日期工具栏在内部滚动时保持可见。
- 扩展包原图通过 Firestone 的公开路径和 npm BoosterType 数据交叉核对，本地保存；对应清单见 `../../../assets/pack-art/README.md`。全部系列用通用卡包堆；未知自定义系列用明确的通用回退，不使用错误系列图。已知系列改名仍保留素材身份。
- 记录需明确拥有 `cardDetails` 或演示明细标记，才能在品质数量上显示卡面预览；仅有“日志识别”来源标签不够，手动记录永不伪造明细。预览按品质逐张展示，重复卡也按张数保留。演示样本包含 1/2/3 张传说。
- 卡面预览使用浏览器顶层 popover，避免被台账滚动区裁掉；悬浮、键盘聚焦和点击均可打开。滚动、Escape、离开或点击外部关闭，多卡使用局部横向滚动与可见区按需加载。
- 单次历史悬浮与最近实包弹窗使用同一份卡牌明细生成界面，普通、金色、异画卡面分别传入对应品质；当前数据仍为明确标记的演示样本。
- 浏览器检查：1633×1244 与 600×800，验证十列双向排序、详情布局、禁用日期、有效日期筛选、卡包原图加载、1/2/3 张悬浮预览、无明细不预览、日历 Escape 和窄屏不撑宽。

最新验证结果：构建通过，开包相关 5 项模型测试通过，浏览器 V3/V4 覆盖详情分组、十列双向排序、原图、可选日期和按张数卡面预览。全量测试为 22/23 通过，失败项位于 `tests/deck-model.test.js:65`，为套牌收藏排序断言；本轮未修改该测试或套牌排序实现。

## 最新布局与一致性修正

单次历史取消独立日期分组行，日期与时分并入每条系列名下方，与卡包类型同一行显示。数字不再用下划线区分可悬浮项，预览能力保留。

历史表按可用高度自动分批（1116×884 实测每批 5 条），可手动选择 5/10/20 条。日期/系列筛选变化重置批次，翻批同步选中该批记录。筛选合计统计全部符合条件的记录；仅表格明细分页，合计与顶部指标不分页。选中摘要压缩为单行，减少留白。

详情原先独立生成的五张卡已移除，改为与悬浮、最近实包完全相同的 `recordedCards` 明细。优先展示高稀有度，支持品质筛选，每批五张；没有明细则只展示说明，不生成不存在的卡面。浏览器已对比确认同条记录的“伟岸的德拉克雷斯”在悬浮和详情中一致。

本次在 1116×884 与 1633×1244 验证：无日期分组、行内日期、数字无下划线、悬浮与详情一致、分批/筛选/选中同步、手动无卡面、页面无横向溢出。构建与开包相关 5 项模型测试通过。
